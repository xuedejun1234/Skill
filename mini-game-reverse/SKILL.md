# 通用小游戏逆向模板

以具体问题为中心，串起「目标包 → 文件/资源地图 → 静态与运行证据 → 最小重建 → 对目标状态验证」。先读现有索引和日志，再决定需要哪一种分析；不要为了“逆向”而全量扫描。

开始时复制 [调查记录模板](assets/investigation-template.md) 到工作项目。目标是从缓存目录快速找包时，先读 [缓存包快速定位](references/fast-package-triage.md)；工具细节读 [工具与定位手册](references/tool-playbook.md)。回顾已完成案例时读 [Unity/IL2CPP 案例](references/case-study-fkxyx-unity.md) 或 [Cocos 案例](references/case-study.md)。

## 工作流程

1. **确认对象与交付。** 记录包路径、平台/游戏 ID、散列、版本、期望交付（资源导出、行为解释、可运行工程或缺陷修复）。包名/图标/标题冲突时，用启动图、页面标题、包清单和用户线索相互确认；不根据一个文件名直接认定目标。
2. **隔离并盘点。** 保留原包只读；分开原始包、解包/暂存、恢复工程、构建输出。快速列文件、大小、格式、清单、入口、分包和引擎标记，复用已有报告。大任务用文件记录进展，避免重复分析。
3. **按引擎建索引。** 以 manifest/序列化引用串起资源 ID、bundle、导入文件、原生文件、图集、场景和预制体。Cocos UUID、Unity GUID/AssetBundle、小游戏自定义 ID 不能混用；文件存在、被引用和运行时成功渲染是三个不同结论。
4. **从问题选静态证据。** 先用 `rg`、source map、资源索引和错误栈缩小范围，再选 REA 的 JavaScript、托管元数据、二进制或 WASM 能力。只选相关文件与模块；保存目标散列、Evidence ID、覆盖范围和限制。类名、字段名、DummyDll 签名只能提供线索，不能冒充方法体或完整逻辑。
5. **需要时取得运行证据。** 在用户指定/授权的模拟器、浏览器或引擎里重现目标状态，记录第一条异常、调用链、事件顺序和画面。截图证明当时可见状态；静态代码证明可能路径；只有目标交互的受控运行才证明实际行为。若目标运行环境不可用，标明未测，继续独立的静态工作。
6. **定位因果链并重建。** 追踪输入 → 事件处理 → 状态/资格判断 → 数据和资源 → 动画/渲染 → 胜负或完成条件。优先修最早阻断点和最小层；保留 ID 映射及原证据。如果原始方法体不可得，明确写“按证据重建”，不要称为原逻辑反编译。
7. **核对实际执行层。** 检查编辑器当前场景、序列化对象、资源引用、脚本编译和真正加载的预览/构建输出。Creator 可能运行旧 chunk；Unity 场景可能只在根对象挂控制器并动态绑定按钮。只改源文件后还要按项目流程刷新、构建或保存相应层。
8. **按目标验收并报告覆盖面。** 对用户指出的关卡、按钮和失败/成功状态逐项核对。区分“提取到的文件数”“已实现/支持的机制数”“实际运行验证的状态数”。构建成功不代表玩法验证完成；未验证和未知机制要留在清单里。

## 优先回答的调查问题

- 我们正在分析哪个具体包/版本？入口与子包在哪里，目标截图/崩溃来自哪个版本？
- 用户要的是资源清点、原行为解释，还是恢复工程可玩？验收状态是什么？
- 目标素材/逻辑是包里缺失、引用断开、运行时覆盖、执行时序问题，还是功能根本未重建？
- 证据是文件清单、静态调用关系、元数据签名、用户截图，还是重放行为？覆盖完整吗？
- 原始实现无法恢复时，哪些部分可由数据、资源和观察重建，哪些机制仍未知？

## 工具路由

- 文件和文本定位优先 `rg --files`、`rg -l`、定点片段读取；结构化数据用 PowerShell/Python/Node 生成可追踪索引。
- 原生发布物/压缩脚本/托管元数据优先选择 REA 对应的分析工具；REA 不是万能解包器，也不自动生成 Unity/Creator 工程。具体工具及限制见工具手册。
- 运行时使用当前可用的小游戏开发工具、浏览器/设备控制或 Unity MCP；使用前确认目标实例、项目状态和工具 schema。没有运行时权限或连接时不把静态分析写成运行验证。
- 恢复工程用对应引擎编辑器与 Console/构建日志；改资源时检查导入设置、GUID/UUID/ID 以及序列化引用。

## 证据与边界

- 为每条结论标记：**观察**（直接看到/日志/文件）、**推断**（由线索得出）、**验证**（目标状态重放通过）或**未知**。
- 分析器超时或只返回 partial graph 时保留部分结果与覆盖率，不把缺边解释为没有调用。
- 记录资源数量、关卡配置数量和可玩范围时分别计数；CSV/Prefab/函数签名存在不等于对应功能已支持。
- 用户授权的具体修复不自动扩大到广告、付费、线上账号或外部服务；离线重建的在线接口应标为占位。
- 用户未要求运行测试/操作运行中的应用时，不擅自开启破坏性或有状态操作；先完成可独立进行的只读分析。
